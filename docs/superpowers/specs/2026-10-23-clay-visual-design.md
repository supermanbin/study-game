# 软萌黏土视觉风格 · 设计文档

日期：2026-10-23
状态：已确认

- `docs/superpowers/specs/2026-10-22-physics-juice-design.md`（物理与动画）

本文只管外观。玩法、规则、物理、时序一律不变。

样张（用户已认可）：`.superpowers/brainstorm/5451-1792720923/content/3d-style.html`（选项 B）和 `.../clay-game.html`（游戏画面）。两份都不进 git。下文第 4 节的数值就是从样张的 CSS 抄过来的。

## 1. 为什么改

用户试玩后提出“设计太丑”“所有图像元素增加立体感”。用户在三种立体风格（糖果光泽 / 软萌黏土 / 玻璃弹珠）中选了 **B. 软萌黏土**，并认可了游戏画面样张，以及以下几点提议：
- 全部页面统一风格；
- 配色整体变暖；
- 特效也换成黏土风；
- 灰球改成“褪色黏土”。

## 2. 目标、非目标、反目标

**目标**
- 所有页面的所有图形元素，都呈现软萌黏土的立体感：哑光、圆鼓鼓、柔和的外投影，加上左上亮、右下暗的内阴影。页面包括：启动、首页、选关、游戏、结算、口诀卡册、设置。
- 配色变暖，与样张一致。
- 在任何屏幕像素密度下都清晰（沿用 `RENDER_SCALE` 方案）。

**非目标**
- 不改玩法、规则、物理参数、碰撞形状、时序、语音和音效。
- 不改页面布局和信息结构。元素的位置和尺寸基本保持，只换外观；为了立体感需要的小幅尺寸调整可以做。
- 不引入外部图片或字体素材。
- 不做真实的黏土纹理（指纹、颗粒）。

**反目标**
- 题目、数字、算式对比度下降，孩子看不清。数字球上的文字必须清晰可读，灰球上的数字也要能认出来。
- 风格不统一，比如游戏里是黏土、菜单还是平面色块。
- 性能明显下降。几十个球同屏时，帧率不能比现在低，所以不能给每个物体挂实时滤镜。
- 立体元素的碰撞体和外观对不上，比如阴影让球看起来比碰撞体大，点击边缘点不中。

## 3. 方案

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A. 运行时用 Canvas 2D 生成黏土贴图（已选）** | 启动时用 Canvas 2D 的径向渐变、阴影画出每种元素，生成 Phaser 贴图后复用 | 效果接近样张；按 `RENDER_SCALE` 生成，所以清晰；改色改参数方便；不需要素材。代价是要为每种元素写绘制代码，尺寸可变的元素要按尺寸生成 |
| B. 美术图片（AI 生成或手绘 PNG） | 每个元素准备图片 | 质感最强；但没有素材来源，迭代慢，还要处理多倍图和版权 |
| C. Phaser 矢量绘图 + WebGL 滤镜 | 在现有绘图上叠阴影、发光 FX | 改动最小；但做不出好的渐变和内阴影，每个物体挂 FX 会伤性能 |

用户选择了 **方案 A**。

## 4. 黏土材质规范

所有黏土元素都由同一个“黏土绘制器”生成。规则如下：

- **底色**：元素的主色，纯色、哑光，不加整体的渐变高光。
- **外投影**：向右下偏移，偏移约为元素尺寸的 8%～12%，柔和模糊，颜色是主色加深后的半透明色。
- **内阴影**：
  - 右下内侧加深，约为尺寸的 10%～12% 的柔边；
  - 左上内侧提亮，约为尺寸的 8%～10% 的柔边，偏白。
  - 两者合起来形成鼓起来的感觉。
- **凹陷元素**（警戒线小点、未亮的血格、未解锁的格子、开关槽）：内阴影反过来，左上暗、右下亮，没有外投影。
- **褪色黏土**（灰球、禁用按钮、未点亮的口诀卡）：
  - 主色 `#d9d0c5`，文字 `#9b8f82`；
  - 立体感保留，但投影更浅。
- **文字**：
  - 球上的数字是白色加很轻的下投影；
  - 面板上的文字用深棕 `#5a4636`；
  - 文字本身不做黏土效果。
- **生成清晰度**：贴图按 `RENDER_SCALE` 倍分辨率生成，显示时按 1/`RENDER_SCALE` 缩放回设计尺寸。
- **贴图与碰撞**：
  - 球体本身的半径等于碰撞半径（数字球 42，算式球 52）。外投影画在半径之外，贴图要为它留白；
  - 通过设置贴图原点，让球体圆心与碰撞中心重合；
  - 点击判定仍然用碰撞圆，与球体本身的可见边缘一致。
- **球的分层与旋转**：
  - 球分成两层：
    - 底层不旋转：外投影、底色和内阴影，光永远从左上来；
    - 上层随物理旋转：只有一条白色哑光短条纹，用来表现滚动。
  - 数字文字始终正向。

## 5. 各页面改动清单

**通用组件**（所有页面复用）：
- 黏土按钮：替换现有 `createButton` 的外观。按下时投影缩小、整体下沉约 3 像素。禁用时是褪色黏土。
- 黏土面板：圆角矩形，鼓起。
- 黏土信息牌：小圆角矩形，鼓起。
- 页面背景：奶油渐变。

**启动、首页**：
- 标题文字用深棕；
- 标题下方可以加一组装饰用的黏土球（静态，不参与物理）；
- 三个按钮换成黏土按钮。

**选关**：
- 6 个关卡块做成黏土面板；
- 星星做成黏土星（亮：柠檬色；暗：凹陷褪色）；
- 锁做成黏土小锁图形，替换 🔒 emoji（emoji 在不同电脑上显示不一样）。

**游戏**：
- 题目栏：鼓起的黏土面板。
- 得分、连对、时间、两个道具：黏土信息牌（道具牌用浅天蓝底）。
- 弹珠钉：小黏土钉。被撞时闪一下，可以是短暂变亮加放大。
- 球：
  - 黏土球，颜色循环使用 4.1 的球色；
  - 保留旋转条纹（白色哑光短条，表现旋转）；
  - 数字始终正向；
  - 算式球同样处理。
- 灰球：褪色黏土。
- 警戒线：一排凹陷的小点，替代红色虚线。
- 地板：厚黏土条，上沿圆角。
- Boss：
  - 黏土公仔小怪兽；
  - 受击时压扁回弹（替代现在的闪白），保留震屏；
  - 血条是 16 个黏土小格，亮或凹陷；
  - 宝箱模式是黏土宝箱。
- 暂停遮罩：半透明奶油色，中间放一块黏土面板，写「暂停中 · 点一下或按空格继续」。
- 错过时的答案提示：显示在一块小黏土信息牌上。

**特效**：
- 爆炸：圆润的黏土颗粒（小圆球、小星星），用球色，带重力下落。
- 冲击波：白色柔边圆环，保留。
- 飘分 `+N`：粗体字，强调色，带厚的浅色描边和一点下投影（与连击大字同一种“黏土字”样式）。
- 连击大字：
  - 用强调色，带厚的浅色描边和一点下投影，看起来像黏土字；
  - 时长、位置不变。
- 火花：小黏土点。

**结算**：
- 结果面板是黏土面板；
- 星星是黏土星；
- 按钮是黏土按钮。

**口诀卡册**：
- 45 张卡是黏土小卡片；
- 已点亮的用球色循环；
- 未点亮的是褪色凹陷样式，口诀文字仍然可读。

**设置**：
- 三个开关做成黏土拨动开关：槽是凹陷的；圆钮鼓起，开为薄荷色，关为褪色。

## 6. 不能退化的东西

- 现有的全部单元测试和 e2e 测试（包括高清屏测试和 e2e 连跑 5 遍）都要通过。
- 按钮文字和 `press(label)` 调试接口保持不变，e2e 依赖它们。
- 点击区域与可见形状一致。
- 每个页面开头仍然先调用 `applyHiDpi`。
- 帧率：游戏中 20 个以上球同屏时不能明显掉帧。
  - 用自动脚本在 2 倍像素密度下，测改动前后的平均帧率，写进实现报告；
  - 改动后不低于改动前的 90%。
- 启动耗时：所有黏土贴图在启动时预先生成，不在游戏中临时生成，避免卡顿。在 2.5 倍像素密度下，生成总耗时不超过约 500 ms，写进实现报告。

## 7. 留给开发者决定的部分

- 绘制器的代码组织。例如 `src/ui/clay.ts` 提供 `clayCircle`、`clayRoundRect`、`clayInset` 这类生成函数，按“种类 + 颜色 + 尺寸 + 缩放”缓存贴图。
- 每种元素的具体阴影参数，在第 4 节的范围内调到接近样张即可。
- 首页装饰球、Boss 公仔、宝箱、锁、星星的具体造型（圆润、可爱、与样张一致）。
- 是否把 Phaser 自带的纯色 `Arc`、`Graphics` 全部替换成贴图图片。只要视觉一致，可以自行取舍（现有测试不依赖对象类型和像素颜色；如果发现有依赖，就改测试的取法，不改测试的目的）。
- 尺寸可变的元素（面板、信息牌、关卡块、按钮）按实际用到的每种尺寸各生成一张贴图并缓存，不用九宫格拉伸，因为九宫格会把内阴影拉变形。信息牌按其中最长的内容定一个固定宽度。
- 样张和第 4 节有出入时：形状和观感以样张为准，数值以第 4 节的范围为准。
- 原有的 `flashWhite` 如果在别处已经不用，可以删掉。

## 8. 本文档中由我（Claude）做出的决定

1. 7 种球色：样张里的 5 种，再补桃粉和湖绿，避免同一题里颜色重复太多。
2. 选关的 🔒 emoji 换成画出来的黏土锁。
3. Boss 受击时改为压扁回弹，不再闪白（闪白和黏土的哑光风格不搭）。保留震屏。
4. 警戒线从红色虚线改为凹陷小点，颜色是浅珊瑚色，仍然能看出是一条线。
5. 暂停遮罩和错过提示也换成黏土面板或信息牌。
6. 按钮按下时有“下沉”反馈。
7. 球分两层：投影和明暗不随球转，只有条纹跟着转，光永远从左上来。
8. 所有贴图在启动时预先生成；帧率不低于改动前的 90%，生成耗时约 500 ms 以内。
9. 飘分用“黏土字”样式，错过时的提示用黏土信息牌。
10. 面板、按钮等按实际尺寸各生成一张贴图，不用九宫格拉伸。
